# 文章示例与模板

这里提供可以直接复制的 Markdown 文件。按实际内容删减章节即可，一篇只有标题和几段文字的笔记也能被站点识别。

本目录位于仓库根目录，属于写作素材。复制到 `src/` 的对应目录后，文章才会进入站点的列表、侧边栏和搜索。

想先看填写后的样子，可以打开[知识笔记示例](./已填写示例/知识笔记示例.md)：它用一个简单的 Linux 路径知识点展示标题、摘要、正文、代码和待验证项如何配合。

## 先选一个模板

| 想记录什么 | 可复制的文件 | 放置示例 |
| --- | --- | --- |
| 随手记一点，暂时不写任何元信息 | [最简笔记.md](./最简笔记.md) | `src/knowledge/linux/今天的学习记录.md` |
| 概念、原理、用法和自己的理解 | [知识笔记.md](./知识笔记.md) | `src/knowledge/linux/设备树学习笔记.md` |
| 实际动手的步骤、观察结果与数据 | [实验记录.md](./实验记录.md) | `src/experiments/023-串口收发实验.md` |
| 某个问题是怎么排查和处理的 | [Debug记录.md](./Debug记录.md) | `src/debug/屏幕白屏排查.md` |
| 常用命令和参数，方便随时查 | [命令速查.md](./命令速查.md) | `src/cheatsheet/串口调试命令.md` |
| 某个项目的设计、接口、模块或进展 | [项目文档.md](./项目文档.md) | `src/projects/1-smart-watch/显示模块笔记.md` |

同一件事可以只写一篇，也可以在内容足够多时拆开。例如学习 SPI 原理可以写知识笔记，实际点亮屏幕可以写实验，白屏的排查过程可以单独写 Debug。判断依据是自己以后会怎样查找这段内容。

## 怎么使用

1. 复制所需模板到上表对应的目录，也可以放进该目录的子目录。
2. 把文件改成自己的名称，例如 `设备树学习笔记.md`。中文文件名可以使用；避免 `#`、`?`、`%` 等 URL 特殊字符。
3. 替换标题、日期和填写提示，删除不需要的章节，保存自己的内容。

现有栏目下新增文章，无需修改导航配置或登记文章列表。开发预览会自动更新，线上内容在正常构建部署后更新。

`index.md` 用于首页或目录页，不适合作为普通笔记文件名。标记为 `categoryPage: true` 的页面也是导航页，不会计入普通文章。

## 文件顶部这一段怎么写

模板中的两个 `---` 之间是 frontmatter，也就是文章的可选元信息：

```yaml
---
title: 设备树学习笔记
description: 记录节点、属性和驱动匹配的理解
date: 2026-10-28
tags:
  - 设备树
  - Linux
platform:
  - i.MX6ULL
status: learning
difficulty: beginner
---
```

整段可以省略，参考[最简笔记](./最简笔记.md)。需要使用元信息时，将它放在文件最顶部，字段按需保留。

| 字段 | 用途 | 不填时 |
| --- | --- | --- |
| `title` | 列表与导航中的文章标题 | 先读取正文的 `# 一级标题`，再回退到文件名 |
| `description` | 列表中展示的一句话摘要 | 从正文提取摘要 |
| `date` | 记录日期，格式为 `YYYY-MM-DD` | 日期排序时排在有日期的记录后面 |
| `tags` | 关键词数组，帮助搜索和细分筛选 | 不展示标签 |
| `platform` | 实际使用的开发板、芯片或环境 | 不展示平台 |
| `status` | 记录进度 | 仍收录在“全部”中，不进入进行中或已完成筛选 |
| `difficulty` | 可选难度：`beginner`、`intermediate`、`advanced` | 不展示难度 |
| `category` | 实验或 Debug 的分类，可写字符串或数组 | Debug 可从分类子目录继承分类 |

模板日期只是示例，使用时改为自己的记录日期。首页“最近记下的”按 `date` 排序，编辑正文并不会自动修改这个日期。

`tags` 和 `platform` 推荐按示例每行写一项，缩进使用空格。正文的一级标题通常和 `title` 保持一致，方便自己维护。

## 状态怎么选

| 类型 | 正在记录或验证 | 确认完成后 |
| --- | --- | --- |
| 知识笔记 | `learning`，学习中 | `done`，已验证 |
| 实验记录 | `doing`，进行中 | `done`，已验证 |
| Debug 记录 | `debugging`，排查中 | `solved`，已解决 |
| 命令速查、项目内文档 | 可省略 | 可省略，按需要使用 `doing` / `done` |

模板默认使用未完成状态。把实际命令、日志和结果写下来后，再决定是否更改状态；没有做过的验证保留“待验证”即可。

项目卡片的 `project.json` 中，`status` 是展示用的中文文字，例如“进行中”“规划中”，和上表的文章状态字段分别维护。

## 新建一个知识分类

以增加“开发工具”分类为例：

```text
src/knowledge/tools/
├── index.md
└── 我的工具笔记.md
```

将[知识分类首页.md](./知识分类首页.md)复制为 `src/knowledge/tools/index.md`，再往同目录写笔记。模板中的 `category="tools"` 与分类目录名一致；如果使用别的目录名，修改这一处参数即可。

这是分类首页的一次设置，后续新增文章只需放入 Markdown。分类图标可选，至少有一篇文章时首页和知识库分类卡片会展示该分类。

## 新建一个项目

将[新项目示例](./新项目示例/)整个文件夹复制到 `src/projects/6-example-project/`：

```text
src/projects/6-example-project/
├── project.json
└── index.md
```

修改 `project.json` 中的项目名称、介绍和实际状态，再填写 `index.md`。示例省略了 `link` 和 `sidebar`，站点会自动选用 `index.md` 作为入口，并发现项目中的 Markdown 文档。

接着可以把[项目文档.md](./项目文档.md)复制到该项目里，改名为 `硬件接线.md`、`显示模块.md` 等；子目录中的文章也会自动进入侧边栏。已有项目新增文档时，只复制 Markdown 就够了。

新建顶级栏目仍需配置全站导航，这套模板不代表任意顶级目录都会自动变成栏目。

## 正文里常用的写法

### 代码与日志

````markdown
```bash title="查看系统信息"
uname -a
```

```text title="实际输出"
在这里粘贴实际输出。
```
````

命令和实际输出分开写，回顾时更容易区分操作与结果。没有实际输出时，可以先删去输出块。

### 图片与关联文章

图片可以放在文章附近的 `images/` 目录。先放入真实文件，再引用它：

```markdown
![接线图](./images/接线图.png)
```

关联文章使用 Markdown 链接，路径按文章实际位置填写：

```markdown
[另一篇笔记](./另一篇笔记.md)
```

模板里的图片与关联链接占位放在 HTML 注释中。实际文件存在后再取消注释，构建时会检查这些链接。

### 备忘和长日志

```markdown
::: tip 备忘
写下容易忘记的前提条件。
:::

::: details 完整日志
在这里粘贴较长的日志。
:::
```

更完整的本地预览、部署和内容扩展说明见[使用手册](../src/USAGE.md)。
