# 嵌入式视频开发入门路线图

做嵌入式视频开发半年了，从零开始一路摸爬滚打。经常有人问我：「想做嵌入式视频，该从哪里入手？」

索性把我自己的学习路径整理出来，形成这张路线图。

---

## 总体路线

```
Linux 基础 → 驱动基础 → Camera → V4L2 → ISP → 视频编码 → 网络传输 → AI
   ↓            ↓          ↓       ↓       ↓        ↓           ↓
 C语言        设备树     Sensor   缓冲     3A      H.264      RTSP
 Shell        I2C/SPI   MIPI    MMAP    ISP     MPP        WebRTC
 Makefile     驱动模型  采集流程 格式    图像质量  FFmpeg    流媒体
```

---

## 第一阶段：Linux 基础（2~4 周）

### 要学什么

- **C 语言**：指针、结构体、内存管理、文件操作
- **Linux 常用命令**：文件、进程、网络、调试工具
- **Shell 脚本**：基础语法、常用命令组合
- **Make / Makefile**：理解编译链接过程
- **交叉编译**：arm-linux-gcc 工具链使用

### 建议实验

- 写一个多文件读写的 C 程序
- 写一个简单的 Shell 脚本处理日志
- 用 Makefile 管理一个多文件 C 项目
- 交叉编译程序并在开发板上运行

### 为什么重要

嵌入式视频开发本质上还是 Linux 开发。Linux 基础不牢，后面寸步难行。

---

## 第二阶段：驱动开发基础（3~5 周）

### 要学什么

- **设备树（Device Tree）**：节点、属性、compatible 匹配
- **I2C 子系统**：协议、驱动框架、用户空间操作
- **GPIO 子系统**：GPIO 控制、中断
- **Linux 驱动模型**：platform bus、probe 机制
- **字符设备驱动**：file_operations、ioctl

### 建议实验

- [#021] Camera Sensor I2C 通信验证
- [#018] I2C 时钟频率测试
- 写一个简单的 GPIO 按键驱动
- 用设备树配置一个 LED 节点

### 为什么重要

Camera Sensor 是通过 I2C 配置的，电源、复位、PWDN 都是 GPIO 控制的。不懂驱动，Sensor 都点不亮。

---

## 第三阶段：Camera 与 V4L2（4~6 周）

### 要学什么

- **Sensor 原理**：Bayer 阵列、曝光、增益、像素格式
- **MIPI CSI-2**：D-PHY、lane 数、带宽计算
- **V4L2 子系统**：设备节点、ioctl、缓冲管理
- **MMAP 模式**：申请缓冲、mmap 映射、入队出队
- **采集流程**：open → set_fmt → reqbuf → mmap → streamon → dqbuf 循环

### 建议实验

- [#022] V4L2 MMAP 视频采集实验
- [#017] YUYV 转 NV12 格式转换
- 用 v4l2-ctl 调试 Sensor
- 保存 RAW 图并查看

### 为什么重要

这是嵌入式视频开发的核心基础。视频链路从 Sensor 开始，经过 V4L2 到用户空间，这是一切的起点。

---

## 第四阶段：ISP 与图像质量（3~4 周）

### 要学什么

- **ISP 基本模块**：BLC、LSC、AWB、AE、AF、Demosaic
- **3A 算法**：自动曝光、自动白平衡、自动对焦
- **图像质量评估**：分辨率、噪点、色彩、动态范围
- **ISP Tuning**：调整参数改善画质

### 建议实验

- 调整 Sensor 曝光/增益观察画面变化
- 对比不同 AWB 模式下的色彩表现
- 调整 ISP 参数对比画质差异

### 为什么重要

Sensor 出来的 RAW 图不能直接用，必须经过 ISP 处理。画质好不好，80% 取决于 ISP Tuning。

---

## 第五阶段：视频编码（3~5 周）

### 要学什么

- **YUV 像素格式**：YUYV、NV12、YUV420P 的区别
- **H.264 编码原理**：I/P/B 帧、GOP、码率控制
- **硬件编码**：Rockchip MPP 编码 API
- **RGA 图形加速**：格式转换、缩放、旋转
- **FFmpeg**：转码、推流、滤镜

### 建议实验

- [#020] MPP H.264 硬编码实验
- [#017] YUYV 转 NV12 格式转换
- 对比不同码率下的画质
- 对比不同 GOP 下的压缩率

### 为什么重要

原始视频数据量太大，必须编码后才能存储和传输。硬件编码是嵌入式视频的核心能力。

---

## 第六阶段：网络传输（3~4 周）

### 要学什么

- **RTSP 协议**：信令交互、SDP 描述
- **RTP / RTCP**：打包、时间戳、丢包重传
- **Live555**：RTSP Server / Client 开发
- **FFmpeg 推流**：RTMP、RTSP 推流
- **网络调试**：tcpdump、wireshark 抓包分析

### 建议实验

- [#016] RTSP 推流测试
- 用 ffplay / VLC 拉流测试
- 测试不同网络下的延迟
- 抓包分析 RTP 包结构

### 为什么重要

视频最终是要通过网络传输的。RTSP 是安防和监控领域最主流的协议。

---

## 第七阶段：进阶方向（按需选择）

### 音频方向

- ALSA 音频采集播放
- AAC 编码
- 音视频同步

### AI 方向

- RKNN 模型转换
- 目标检测部署
- NPU 性能优化

### 多路方向

- 多路视频采集
- 多码流编码
- 视频拼接
