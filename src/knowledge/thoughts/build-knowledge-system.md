# 从零搭建嵌入式视频开发知识体系

做嵌入式视频开发半年了，从最开始连 V4L2 是什么都不知道，到现在能独立完成 Sensor 调试、MPP 编码、RTSP 推流整条链路。

但我发现一个问题：**知识是零散的**。

每次遇到新问题，还是要去翻之前的代码、查收藏的网页、翻聊天记录。知识没有沉淀下来，更没有形成体系。

于是我决定用 VitePress 搭一个自己的「知识花园」，把学到的东西系统化地整理出来。

---

## 为什么要做这件事

### 1. 遗忘曲线太残酷

一个知识点如果不用，三个月后基本就忘了。等到再遇到同样的问题，又要从零开始查。

写下来，是对抗遗忘最好的方式。

### 2. 嵌入式视频的链路太长了

```
Sensor → I2C → MIPI → V4L2 → ISP → RGA → MPP → H.264 → RTSP → 播放器
```

这一整条链路上，任何一个环节出问题都可能导致最终画面不对。如果对每个环节只有模糊的理解，排查问题就像盲人摸象。

**只有把每个点都搞透，并且理解它们之间的关系，才能真正掌控整条链路。**

### 3. 费曼学习法

教别人是最好的学习方式。把一个知识点写成清晰的文章，本身就是一次深度梳理。写不明白的地方，就是还没真正理解的地方。

---

## 我的知识体系结构

我把内容分成了几个模块，每个模块有不同的定位：

### 📚 知识库

系统化的知识整理，偏理论和原理。每篇文章讲清楚一个知识点。

- **Camera / V4L2**：Sensor、MIPI CSI、V4L2 子系统、ISP
- **音视频**：YUV 格式、H.264 编码、MPP、FFmpeg、RTSP
- **Linux / 驱动**：mmap、I2C、设备树、内核驱动
- **项目管理**：Git、构建系统、调试技巧

### 🧪 实验记录

动手做的每一个实验，按时间编号。每个实验有明确的目标、环境、步骤、代码、结果、结论。

- 实验编号连续（#001, #002, #003...）
- 不管成功失败都记录
- 附上代码和数据

### 🐛 Debug 记录

踩过的每一个坑。**从现象到根因到解决方案**，完整记录排查过程。

- 问题现象和环境
- 排查思路和过程
- 根因分析
- 解决方案
- 经验总结

> 这是最有价值的部分。因为踩过的坑，以后一定还会再踩。

### ⚡ 命令速查

常用命令的速查表。不用每次都去 Google，直接搜自己的速查表。

- V4L2 命令
- Linux 常用命令
- FFmpeg 命令
- Git 命令

### ✍️ 博客

比较完整的技术文章、学习心得、项目总结。

## 为什么选 VitePress

1. **Markdown 写作**：专注内容，不用管排版
2. **静态站点**：部署简单，GitHub Pages 直接托管
3. **Vue 组件**：需要的时候可以写自定义组件（比如首页的卡片、列表）
4. **搜索功能**：内置全文搜索，找东西很方便
5. **响应式**：手机上看也没问题
